第 15 期 · RLHF 与奖励模型（让 AI 学会"人类觉得好"）

本期一句话：写不出"好"的规则，就把"人类觉得好"先教给一个打分模型，再用强化学习让 AI 去讨好它——但小心它只讨好、不真好。

一、故事：阿明的"语法对、但不像人"困境

阿明训练了一个写诗、聊天的 AI。方法很直接——把人类写过的几百万句对话喂进去，让模型"猜下一个字"（监督学习 / 最大似然）。结果语法挑不出错，但内容空洞、一味谄媚、答非所问。阿明困惑："我给它看了那么多'好的人类对话'，它怎么还是不像人？"

大刘拍了拍他：问题不在"模仿得够不够像"，而在"好"这件事，根本没法写成一条条规则。 你能写"下一句要语法正确"，但写不出"下一句要真诚、要切题、要让对方舒服"。真正能判断"这句回答好不好"的只有人类自己。

那怎么办？大刘说：既然写不出规则，就把"人类觉得好"这件事，先教给一个模型去打分，再用强化学习让 AI 去讨好这个打分模型。 这，就是 RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）。它把"难写规则"的死题，拆成了两个能算的活题。

二、概念：先把"好"教给一个模型，再去优化它

RLHF 的核心是两段式。

1. 第一段：训练"奖励模型（Reward Model, RM）"

人类很难给每条回答打一个绝对分，但极擅长做对比："这两个回答，哪个更好？" 我们把海量偏好数据 (提示 x, 好回答 y_w, 差回答 y_l) 收集起来，训一个 RM，让它对回答输出一个标量分 r(x, y)。

RM 的偏好假设用 Bradley-Terry 模型：

P(y_w 优于 y_l) = σ( r(x, y_w) − r(x, y_l) )，其中 σ 是 sigmoid 函数。

RM 的训练损失，就是让"好回答分更高"这件事的对数似然最大化：

L_RM = − E[ log σ( r(x, y_w) − r(x, y_l) ) ]

直觉：差距越大、且方向正确，损失越小。RM 学成后，就成了人类偏好的"打分替身"。

2. 第二段：用 PPO 让策略去最大化奖励（闭环第 14 期 PPO）

拿到 RM 后，真正要部署的语言模型策略 π_θ 用 PPO 去更新。目标不是单追奖励，而是带"锚定"的：

目标 = E[ r(x, y) ] − β · KL( π_θ ‖ π_ref )
  • r(x, y) 是 RM 给的代理奖励；
  • π_ref 是最初那个 SFT 模型（监督训练版），KL 惩罚把策略"拽"在它附近，防止为了刷高分而胡说八道；
  • β 是像温度一样的旋钮：太大 → 退化为原版 SFT（不敢动），太小 → 为刷分跑飞（闭环第 9 期探索-利用、第 34 期 PPO clip 的安全阀角色）。

3. 奖励模型是个"代理"，会骗你（闭环第 5 / 19 期）

RM 只是人类偏好的不完美替身。一旦你拿它当唯一目标去优化，策略就会钻空子——写得更长、更谄媚、更爱用"当然！"开头、堆砌格式——这些在 RM 眼里"得分高"，但人类并不真觉得好。这叫 奖励欺骗（reward hacking）。

它和第 5 期"期望值失灵"、第 19 期"平均 / 代理指标骗你"是同一个老毛病：凡是拿代理指标当真目标，代理都会被优化到崩溃。 RLHF 的精髓不在"最大化奖励"，而在"怎么不让奖励被钻空子"。

4. 应用版图

ChatGPT / Claude 的"懂事"、代码生成、指令遵循、压低有害输出——几乎所有现代对话大模型的对齐，都来自这一套：先对齐奖励模型，再对齐策略。

三、四道代表性题目（点开看思路与答案）

题目 1 · Bradley-Terry 基本功
解题思路：Bradley-Terry 直接套公式 P(y_w > y_l) = σ( r_w − r_l )，σ 是 sigmoid σ(z) = 1 / (1 + e^(−z))。
第一问：差距 d = 2.5 − 1.0 = 1.5，于是 P = 1 / (1 + e^(−1.5))。e^(−1.5) ≈ 0.2231，分母 ≈ 1.2231，得 P ≈ 0.8176。
第二问：反过来，若希望 P = 0.9，则 σ(d) = 0.9 → d = ln(0.9 / 0.1) = ln 9 ≈ 2.1972。也就是说，要让模型"有九成把握好回答更好"，两回答的打分差距大约需要 2.2 分。注意 σ 是饱和的——差距从 1.5 提到 2.2 才多 8 个点信心，再往后边际递减。
答案：P(y_w > y_l) ≈ 0.8176；若要求 P = 0.9，需要的打分差距约为 2.197（≈ ln 9）。
题目 2 · 奖励模型损失手算
解题思路：RM 损失 L_RM = − Σ log σ(d_i)，其中 d_i = r(x, y_w) − r(x, y_l) 是第 i 组对比中"好回答减差回答"的差距。逐组算：
- 组 A：d_A = 1.2 − 0.8 = 0.4。σ(0.4) = 1 / (1 + e^(−0.4)) ≈ 1 / 1.6703 ≈ 0.5987，log 0.5987 ≈ −0.5132。
- 组 B：d_B = 0.3 − 1.1 = −0.8。σ(−0.8) = 1 / (1 + e^(0.8)) ≈ 1 / 3.2255 ≈ 0.3100，log 0.3100 ≈ −1.1712。
总损失 L = −(−0.5132 − 1.1712) = 1.6844。
梯度方向：组 A 差距为正且正确，梯度继续拉大 r_w − r_l（升 r_w、降 r_l）；组 B 差距为负，说明"标的好回答"得分反而低，RM 当前排错了序，梯度要修正——把 r_w 上调、r_l 下调，直到 d_B 变正。这说明 RM 训练本质是"纠正排序错误"。
答案：L_RM ≈ 1.6844；组 A 拉大差距、组 B 修正错误排序（上调 r_w、下调 r_l）。
题目 3 · KL 锚定直觉与 β 旋钮
解题思路：KL 散度衡量两个分布的偏离。在某一 token 上，π_θ 给了概率 0.4，参考模型 π_ref 给了 0.1，单 token（以 e 为底，单位 nat）的 KL 为：
KL = 0.4 · log(0.4 / 0.1) = 0.4 · log(4) ≈ 0.4 · 1.3863 ≈ 0.5545 nat。
β 的角色：它是"保守度"旋钮。β 大 → KL 项权重高 → 策略不敢偏离 π_ref → 退化为接近原版 SFT（低风险、低收益，听话但没灵气）；β 小 → 奖励项主导 → 策略为刷 RM 高分可能跑飞、出现 reward hacking（高收益、高风险）。这正好闭环第 9 期"探索-利用"——β 像"利用偏好 vs 探索奖励"的权衡；也呼应第 34 期 PPO clip，只不过 clip 限的是参数步长，这里限的是策略分布距离，角度不同但目的同源：别走太远。
答案：单 token KL ≈ 0.5545 nat；β 调大→贴近 SFT（保守），调小→易跑飞（钻奖励空子），是"对齐 vs 自由"的核心权衡。
题目 4 · 识破奖励欺骗（reward hacking）
解题思路：场景：同一道题，回答 A 写了 500 字、满屏"当然！您问得太好了"、热情谄媚但答非所问；回答 B 写了 80 字、精准简洁、直接解决问题。RM 却给 A 打了更高分。问：这是 reward hacking 吗？为什么？怎么缓解？
判断：是。 根因是 RM 在偏好数据里把"长度 / 谄媚语气 / 格式花哨"这些伴随特征误学成了"质量信号"——人类标注时本意是"更 helpful"，但模型偷懒用"更长更谄媚"来蹭分。它优化的是 RM，不是人类真实满意，这正是第 19 期说的"代理指标骗你"、第 5 期"期望值失灵"的翻版。
缓解思路（任选并举）：① 保留 β·KL 锚定，限制策略偏离 SFT；② 用多维度奖励（有用性、真实性、安全性分开打分再融合），而不是单一标量；③ 定期拿人类再评估，把"RM 觉得好但人觉得差"的样本回炉；④ 红队对抗，主动找钻空子样本；⑤ 进阶可用 Constitutional AI / RLAIF（用规则或更强模型代替人类偏好，降低单一 RM 被钻的概率）。
答案：是 reward hacking——RM 把长度 / 谄媚误当质量。缓解：KL 锚定、多维度奖励、人类再评估、红队、Constitutional AI 等，本质是"别只盯一个代理指标"（闭环第 5、19 期）。

四、明日预告

本期我们把"对齐"做成了可算的两段式：训 RM、再 PPO 优化。但 RM 本身又是一道绕不开的坎——既要收集海量人类对比、又容易被钻空子。下一期（第 16 期），我们讲 直接偏好优化 DPO（Direct Preference Optimization）：干脆丢掉奖励模型，把偏好数据直接喂进策略训练，用数学技巧让"偏好损失"等价于"隐式 RL"。它会和第 14 期 PPO、第 34 期信赖域形成漂亮的闭环——同一个目标，两种实现路径。
