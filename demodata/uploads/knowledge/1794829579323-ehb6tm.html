第 14 期 · 信赖域与 PPO（既大步前进，又不翻车）

一句话：策略梯度（第 13 期）学会了"往好处爬"，但步子太猛会把策略推下悬崖。信赖域（Trust Region）说——别看参数挪了多少，要看策略本身变了多少（用 KL 散度衡量）。PPO 是它最省事的实现：一个 clip 把概率比卡在 1±ε，既敢迈大步、又自动踩刹车。

一、故事：取餐机器人又"疯"了

第 13 期里，大刘给取餐机器人装上了策略梯度 + Actor-Critic，机器人终于不再撞墙，学会自己爬坡优化送餐路线了。可没过几天，阿明发现一个怪病：

机器人有时候学着学着突然疯了——策略全乱套，一会儿满场绕圈，一会儿直冲墙角。一看训练曲线，某一步回报暴跌，之后怎么也救不回来。

大刘盯着曲线说："这叫 performance collapse（性能崩塌）。问题出在你那'步长'上。"

阿明不服："我用的就是 SGD 的学习率 η 啊，跟第 4、5 期一样，学了那么久也没事。"

"错。第 3 期模拟退火里我跟你说过，温度就是步长开关——温度太高就乱跳、太低就冻住。你这里也一样。但还有一个你没想到的事：神经网络的策略是非线性的。"

大刘在白板上画了两行：

  • 参数 θ 只挪了一点点（比如把一个 logit 从 0 改成 10）；
  • 可经过 softmax 之后，策略却从"均匀随机"变成了"几乎 100% 选某动作"。

"你看，参数的 L2 距离很小，策略的 KL 散度却翻天覆地。用'参数步长'当刹车，会严重误判。 真正该约束的，是'策略变了多少'——也就是 KL 散度（第 16、26 期）。这，就是信赖域的思想。"

"那我总不能每步都手算 KL 再解带约束的优化吧？"阿明问。

"聪明人早想好了。PPO（Proximal Policy Optimization） 用一个 clip 把新旧策略的概率比卡在 1±ε 内，不用显式解约束，效果却等价于'在信赖域里迈最大的一步'。走，我教你。"

二、概念讲解

1. 策略梯度的老毛病：步长难调

策略梯度（第 13 期）的更新方向是对的，但步长是两难：

  • 步子太大 → 策略一下跨出信赖域 → 性能崩塌、难以恢复；
  • 步子太小 → 学得太慢、样本浪费。

核心张力：如何既大步前进，又保证不翻车？

2. 信赖域（Trust Region）：约束"策略位移"而非"参数位移"

关键洞察：两个参数向量 θ₁、θ₂ 很接近（‖θ₁−θ₂‖ 小），不等于两个策略很接近。因为策略是参数经过非线性变换（如 softmax）得到的。

所以信赖域方法约束的是新旧策略的 KL 散度：

KL(π_old ‖ π_new) ≤ δ

而不是参数的 L2 范数 ‖θ_new − θ_old‖ ≤ Δ。δ 就是"信赖域半径"——允许策略最多变这么多。

TRPO（Trust Region Policy Optimization） 把目标写成：在 KL 约束下，最大化替代目标（surrogate objective） E[ r_t(θ) · Â_t ]，其中 r_t(θ) = π_θ(a|s) / π_θ_old(a|s)（这就是第 13 期的似然比）。

3. PPO-Clip：把约束变成一行裁剪

PPO 最常用、最省事的版本叫 PPO-Clip。它不显式解 KL 约束，而是直接把概率比裁剪：

L^CLIP(θ) = E[ min( r_t(θ)·Â_t , clip(r_t(θ), 1−ε, 1+ε)·Â_t ) ]

直觉（这就是"刹车"的精髓）：

  • 优势 Â_t > 0（好动作，想提高它的概率）：如果 r_t 涨过 1+ε，裁剪把增益封顶在 (1+ε)·Â_t，防止你贪心对高优势动作过度加码。
  • 优势 Â_t < 0（坏动作，想降低它的概率）：如果 r_t 跌过 1−ε，裁剪把惩罚兜底在 (1−ε)·Â_t，防止你一步把动作彻底砍死。

两边都被卡住 → 无论好坏，策略一步最多移动 ε 比例 → 等价于待在信赖域里。ε 常用 0.1~0.3。

为什么 PPO 这么火？ 它实现简单（几行代码 + 普通 SGD/Adam）、稳定、样本效率不差。ChatGPT / InstructGPT 的对齐训练（RLHF）用的核心算法就是 PPO。

4. 闭环地图（回顾你走过的路）

  • 第 13 期 策略梯度 / Actor-Critic：似然比 r_t=π/π_old、优势 Â_t ← 本期的积木。
  • 第 3 期 模拟退火：温度 = 步长开关；信赖域半径 δ 就是"策略世界的温度"。
  • 第 4、5 期 SGD / 学习率 η：PPO 的更新底层仍是 SGD（第 5 期讲的学习率衰减在这里同样关键）。
  • 第 12 期 目标网络：稳定更新、别让目标乱动 ← 与"别让策略乱动"同构。
  • 第 16、26 期 KL 散度 / 变分推断：KL(π_old‖π_new) 正是这里信赖域的尺子。

5. 一个最小直觉公式表

| 符号 | 含义 |

|---|---|

| r_t(θ) | 新旧策略概率比 = π_θ(a|s) / π_θ_old(a|s) |

| Â_t | 优势估计（第 13 期），>0 好、<0 坏 |

| ε | 裁剪系数（信赖域半径的代理），常 0.1~0.3 |

| clip(x, 1−ε, 1+ε) | 把 x 限制在 [1−ε, 1+ε] 内 |

| L^CLIP | 取 min(未裁剪, 已裁剪) 的保守下界 |

三、四道代表性题目（你来总结，折叠块里有完整思路与答案）

题目 1 · PPO-Clip 概率比与裁剪基本功

某状态 s 下动作 a 的旧策略概率 π_old = 0.4，新策略 π_θ = 0.5，优势估计 Â = +1.0，裁剪系数 ε = 0.2。请手算 L^CLIP 的值，并说明裁剪是否生效。

解题思路：按定义一步步来。
1. 先算概率比 r_t = π_θ / π_old = 0.5 / 0.4 = 1.25。
2. 未裁剪项 = r_t · Â = 1.25 × 1.0 = 1.25。
3. 裁剪项：把 r_t 夹进 [1−ε, 1+ε] = [0.8, 1.2]。因为 1.25 > 1.2，所以 clip(1.25, 0.8, 1.2) = 1.2；再乘优势得 1.2 × 1.0 = 1.2。
4. 取两者较小值：L^CLIP = min(1.25, 1.2) = 1.2。
这是正向优势（Â>0）且概率比冲过了上界 1+ε 的典型情形——裁剪把"贪心推高"封顶，正是信赖域在踩刹车。
答案：L^CLIP = 1.2，裁剪生效（把正向增益封顶在 1.2，防止对高优势动作过度加码）。
题目 2 · 负优势的反向裁剪

同一公式下，旧策略 π_old = 0.4，新策略 π_θ = 0.2（概率被砍低），优势 Â = −0.5，ε = 0.2。手算 L^CLIP，并解释裁剪此时在保护什么。

解题思路：
1. r_t = 0.2 / 0.4 = 0.5。
2. 未裁剪项 = 0.5 × (−0.5) = −0.25。
3. 裁剪项：clip(0.5, 0.8, 1.2) = 0.8（因为 0.5 < 0.8，被托到 0.8）；再乘优势得 0.8 × (−0.5) = −0.4。
4. 取较小值：min(−0.25, −0.4) = −0.4。
这里优势为负（想降低该动作概率），而 r_t 跌破了下界 1−ε。裁剪把惩罚兜底在 0.8·Â = −0.4，而不是让未裁剪的 −0.25（更轻）。等等——min 取的是更小的 −0.4，即裁剪后的更重惩罚？注意：PPO 的 min 提供的是"保守下界"。当概率被砍太狠时，裁剪项给出了"最多只能砍到 1−ε 比例"的约束信号，避免一步把动作彻底砍死（否则后续想恢复都难）。
答案：L^CLIP = −0.4，裁剪生效——当优势为负且概率被砍太多时，PPO 把位移封顶在 1−ε 比例，防止策略一步把动作彻底剔除（保留"翻盘"余地）。
题目 3 · 为什么信赖域看 KL 而不是参数距离

考虑一个二动作策略，logits 经 softmax 输出概率。参数 θ_a 给出 logits = [0, 0]（均匀策略 π_a = [0.5, 0.5]）；参数 θ_b 只把第一个 logit 从 0 改成 10（其余不变），得到 π_b ≈ [0.99995, 0.00005]。请近似计算 KL(π_a ‖ π_b)，并说明：为什么不能用 ‖θ_a − θ_b‖ 作为更新约束？

解题思路：
1. 参数距离：我们只改了一个 logit，幅度 10，所以 ‖θ_a − θ_b‖（单参数情形）≈ 10，看起来"不大"。
2. 但策略已几乎从"均匀"变成"确定选动作 1"。算 KL（以自然对数 nats 为单位）：
- KL(π_a‖π_b) = 0.5·ln(0.5 / 0.99995) + 0.5·ln(0.5 / 0.00005)
- 第一项 ≈ 0.5 × (−0.6931) = −0.3466
- 第二项 ≈ 0.5 × ln(11013) ≈ 0.5 × 9.307 = 4.653
- 合计 ≈ 4.31 nats ≈ 6.2 bits。
3. 结论：参数只挪了"距离 10"，策略 KL 却高达约 4.3 nats（几乎把全部概率压到一个动作）。反过来，两个参数向量 L2 差很大时，策略也可能几乎没变。参数距离≠策略距离，所以信赖域必须用 KL（衡量策略本身的位移），不能用 ‖Δθ‖（只衡量参数位移）。
答案：KL(π_a‖π_b) ≈ 4.31 nats（约 6.2 bits）。因为神经网络非线性，参数小改动可能引策略剧变、大改动也可能无影响；用 ‖Δθ‖ 当约束会严重误判策略位移，故信赖域约束的是 KL 散度。
题目 4 · 自适应信赖域与 PPO 的 KL 早停

TRPO 用硬约束 KL ≤ δ。实践中有一套自适应调节：若某次更新后实测 KL 远小于 δ（步子还能迈更大却没迈），下一轮把 δ 调大；若实测 KL 超过 δ（越界），下一轮把 δ 调小。PPO 没有显式 δ，但常用"KL 早停"：当滚动平均 KL 超过目标 KL 的 1.5 倍时，提前结束本轮 epoch。

若目标 KL = 0.01，当前实测滚动 KL = 0.018，问：应不应该触发早停？并简要说明：为什么 KL 早停比"固定 epoch 数"更稳？

解题思路：
1. 早停阈值 = 1.5 × 目标KL = 1.5 × 0.01 = 0.015。
2. 实测 0.018 > 0.015 → 超过阈值，应触发早停（停止本轮剩余 minibatch 更新）。
3. 为什么比固定 epoch 数稳：固定 epoch 数意味着"无论策略已经漂多远，都再更新 N 步"，后期 minibatch 完全可能把策略推出资讯域、造成崩塌；而 KL 早停用"真实策略位移"当刹车，一旦策略已经移出信赖域就立刻停手，相当于给每轮更新装了自适应保险丝。
答案：0.018 > 0.015，应触发早停。KL 早停用真实策略位移（KL）作刹车，比固定 epoch 数更能防止策略越界崩塌；这与 TRPO 自适应调 δ 是同一思想的两种实现。

  • 关键转向：约束"策略位移"（KL 散度），而非"参数位移"（L2）。
  • PPO-Clip 一句话：L^CLIP = min(r·Â, clip(r,1−ε,1+ε)·Â)，两边裁剪 = 自动刹车。
